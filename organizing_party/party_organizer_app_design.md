# 飲み会幹事アプリ 詳細設計書

**Version 1.2　2026年4月**

---

## 1. システム概要

飲み会の幹事が日時・店舗の候補を登録し、参加者に回答リンクを共有することで、参加可否・日時・店舗希望を収集・集計するWebアプリケーション。

| 項目 | 内容 |
|---|---|
| ターゲット端末 | スマートフォン（メイン） |
| デザイン方針 | シンプル・ミニマル |
| 認証 | ログイン機能なし。幹事はイベント作成時に設定したパスワードで確定操作のみ認証する |
| 招待方式 | 幹事が招待リンクを社内ツール等でシェア |
| パスワード忘れ | 再発行なし。その場合はイベントを作り直す |

---

## 2. 技術スタック

| レイヤー | 技術 | 備考 |
|---|---|---|
| フロントエンド | React + TypeScript | fave.appと同一スタック |
| バックエンド | Supabase（BaaS） | バックエンドコード不要 |
| データベース | PostgreSQL | Supabase内蔵 |
| ホスティング | Vercel | 無料枠・自動デプロイ |
| メール送信 | 対象外（今フェーズ） | 社内ツールで代替 |

### 選定理由

- バックエンドコードをほぼ書かずに済む（Supabase SDK をReactから直接呼ぶ）
- Vercel はリポジトリ連携だけで自動デプロイが完結
- 全サービス無料枠で運用可能
- fave.appと同一のフロント技術スタックで学習コストゼロ

## 3. 画面構成

| 対象 | 画面名 | 説明 |
|---|---|---|
| 幹事 | イベント作成画面 | 日時・店舗候補・パスワードを入力してイベントを作成する |
| 幹事／参加者 | 作成完了画面 | 発行されたトークンURLを表示・コピーする |
| 幹事／参加者 | ダッシュボード（状況タブ） | 回答状況・集計を全員が閲覧できる |
| 参加者 | ダッシュボード（回答タブ） | 参加可否・日時・店舗希望を回答する |
| 幹事 | 確定モーダル | パスワード認証後に日時・店舗を確定する |

## 4. 画面詳細設計

### 4.1 イベント作成画面

幹事がイベントの基本情報・日時候補・候補店舗・パスワードを入力する画面。ログイン不要。

#### 基本情報

| 項目 | 内容 |
|---|---|
| イベント名 | 必須。テキスト入力 |
| 回答期限 | 必須。日付ピッカー |
| 幹事パスワード | 必須。任意の文字列。確定操作時の認証に使用 |

#### 日時候補

| 項目 | 内容 |
|---|---|
| デフォルト件数 | 1件 |
| 最大件数 | 3件 |
| 追加操作 | 「＋候補を追加」ボタンで1件ずつ追加 |
| 各候補の入力 | 日付（必須）＋時間（必須） |

#### 候補店舗

| 項目 | 内容 |
|---|---|
| デフォルト件数 | 1件 |
| 最大件数 | 3件 |
| 追加操作 | 「＋店舗を追加」ボタンで1件ずつ追加 |
| 店名 | 必須。テキスト入力 |
| URL or 住所 | 任意。テキスト入力 |
| 備考 | 任意。テキスト入力（例：予算、料理ジャンル） |

#### バリデーション

- イベント名・回答期限・幹事パスワードは必須
- 日時候補・候補店舗はそれぞれ最低1件必要
- 各日時候補の日付・時間は必須
- 各店舗の店名は必須

---

### 4.2 作成完了画面

「作成する」ボタン押下後に表示される画面。トークンURLが発行される。

| 項目 | 内容 |
|---|---|
| 完了メッセージ | 「イベントを作成しました」のメッセージ表示 |
| トークンURL | 発行されたURLを表示し「コピー」ボタンを配置 |
| 案内文言 | 「このURLを参加者に共有してください」 |
| 遷移 | 「ダッシュボードへ」ボタンでダッシュボードに移動 |

- アプリ側でのメール送信機能は持たない
- 幹事はコピーしたURLを社内ツール等で一斉共有する
- **このURLが唯一のアクセス手段のため、幹事自身もブックマークを推奨**

---

### 4.3 ダッシュボード

トークンURLにアクセスした全員が利用できる画面。タブ形式で「状況」「回答」の2タブを持つ。

#### 4.3.1 回答タブ

**表示情報**

| 項目 | 内容 |
|---|---|
| イベント名 | 読み取り専用で表示 |
| 回答期限 | 読み取り専用で表示 |

**入力項目**

| 項目 | 内容 |
|---|---|
| 名前 | 必須。テキスト入力（自己申告） |
| 参加可否 | 必須。ラジオボタン（参加 / 不参加） |
| 日時選択 | 「参加」選択時のみ表示。チェックボックス（複数選択可） |
| 店舗選択 | 「参加」選択時のみ表示。ラジオボタン（1択） |
| 特記事項 | 「参加」選択時のみ表示。テキストエリア（任意） |

**表示ロジック**

- 「不参加」選択時：参加可否ラジオのみ操作可能。その他の入力項目は非表示
- 「参加」選択時：日時選択・店舗選択・特記事項を表示

#### 4.3.2 状況タブ

全員が閲覧可能。

**サマリーセクション**

| 項目 | 内容 |
|---|---|
| 回答状況 | 回答済み人数 / 全体人数（例：8/12人） |
| 参加内訳 | 参加人数 / 不参加人数 |

**集計セクション**

| 項目 | 内容 |
|---|---|
| 日時集計 | 各候補日時ごとに参加できる人数をバー＋数字で表示 |
| 店舗集計 | 各候補店舗ごとに得票数をバー＋数字で表示 |

**参加者一覧**

| 項目 | 内容 |
|---|---|
| 回答済み | 名前・参加可否・特記事項を表示 |
| 未回答 | グレーアウトで表示 |

**確定ボタン**

| 項目 | 内容 |
|---|---|
| 表示条件 | 回答期限を過ぎた後に表示 |
| 押下時 | パスワード入力モーダルを表示 |
| 認証成功時 | 確定モーダルへ遷移 |
| 認証失敗時 | エラーメッセージを表示 |

---

### 4.4 確定モーダル

パスワード認証後に表示。イベント作成画面と同じレイアウトを参考に構成する。

**確定操作フロー**

1. 状況タブの「確定へ進む」ボタンを押下
2. パスワード入力モーダルを表示 → 認証
3. 日時・店舗ともに最多候補が1つに絞れる場合 → 自動選択済みの状態で確定モーダルを表示
4. 同数候補が存在する場合 → 同数候補のみ選択肢として提示
5. 「確定する」ボタン押下で確定処理を実行

## 5. トークン設計

ログインなし。全員が同一のトークンURLでアクセスする。

| 項目 | 内容 |
|---|---|
| URL形式 | `/event/{eventId}?token={token}` |
| トークン生成 | イベント作成時にサーバーサイドで生成 |
| トークン管理 | DBでイベントIDと紐付けて管理 |
| 幹事の識別 | URLではなくパスワードで行う |

### セキュリティ

- 同一名前からの2回目以降の回答は上書き
- パスワードはハッシュ化してDBに保存する
- パスワード忘れによる再発行は対応しない（イベントを作り直す）
